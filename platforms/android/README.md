# Android wrapper

The APK uses the repository's single `engine` game core, SDL 2.30.12, and SDL_mixer 2.8.1. The vendored `org.libsdl.app` Java files come from the matching SDL 2.30.12 release (`https://www.libsdl.org/release/SDL2-2.30.12.zip`, SHA256 `aa2808d0f2dc6b383c6689bf6d166e2de62db4d58be989e4b052acb31df0fba3`). See `SDL-LICENSE.txt`. Four files have minimal Android runtime permission checks and an Android 33 USB receiver flag patch. No Bluetooth, microphone, or vibration permission was added. Hashes and the exact patch are in `verification/sdl-java-provenance.json` and `verification/sdl-android-permissions.patch`; unchanged files retain their upstream hashes. No lint baseline or blanket suppression is used.

Use JDK 17 or 21, Gradle 8.9, Android SDK API 35, CMake 3.22.1, and NDK 28.2.13676358. Set `ANDROID_HOME` or a local `sdk.dir` before running `gradle :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`. The debug build uses the existing local Android debug keystore; do not generate replacement credentials for an update. No release signing key is configured.

Set `ANDROID_HOME` to your SDK directory and pass `-PpinballNdkPath=<your NDK directory>` to override the development-only fallback path in Gradle. Install SDK CMake 3.22.1, or configure its location in an ignored local.properties. See [the portable build guide](../../docs/BUILD.md#android).

Optionally pass `-PpinballBuildRoot=<absolute output directory>` to place generated outputs and native staging outside the checkout. Source and assets remain in the checkout. APK output then resides in `<pinballBuildRoot>/app/outputs/apk/debug/app-debug.apk`.

When GitHub archive downloads are unavailable, run `./Prepare-Sdl.ps1` to prepare the exact official release sources with recorded hashes. The CMake wrapper reuses these verified local versions. The full source/download cache is ignored; the matching SDL Java sources, limited permission patch, and license are included in the project.

The app package is `com.codex.spacecadetpinball`; arm64-v8a is mandatory. APK assets retain `game/`, `fonts/`, and `audio/` prefixes from the shared `assets` directory. There is no Internet permission or online service.

Before the SDL surface is attached, an APK-generated SHA256 manifest verifies and stages game/font/music files into app-private `files/pinball-content/<manifest-sha256>/assets/`. The Korean font and `audio/TimGM6mb.sf2` music bank are mandatory. Only a fully verified directory is published and selected as the native working directory. Existing caches are verified again; damaged copies are preserved separately and rebuilt. Partial staging is never reused. This cache is separate from the engine's score/settings directory. Failure removes the SDL surface before `SDL_main` can start and shows a recovery message.

Phone tilt and its settings, sensitivity, calibration, detector, and sensor JNI were retired at the user's request. Left, right, and front screen nudge buttons and the original game's Tilt penalty remain. `GameSurface` overrides SDL's `enableSensor` extension point without registering sensors, including SDL's automatic accelerometer. Old `phone_tilt` preferences are ignored; no game INI, scores, or other app data are deleted.

After full engine initialization, `platform_android_ready()` schedules the Activity's `onNativeReady()`. Common input-session initialization uses `nativeResetInputSession` and `platform_reset_input_session`, retaining session advancement and input cancellation. Lifecycle `onResume` never submits an unpause command; only the user's Resume choice sends `platform_notify_pause(0, session)`. A delayed callback checks whether its Activity has been destroyed before touching UI.

Rotation, focus loss, home, lock, back, and pause cancel inputs. Resume requires the user to select Resume. Input-session reset preserves the game's accumulated Tilt penalty and never calibrates or reads a phone sensor.

The SDL surface uses the current window's system-bar, display-cutout, and mandatory-gesture insets on all supported APIs (legacy system-window insets on API 26–29). Insets are converted to additional layout padding after subtracting any fitting already performed by Android. This resizes the actual SurfaceView, so SDL's native resize and normalized touch coordinates share the same rectangle. Insets are recomputed after layout, configuration changes, and focus/resume; there are no fixed pixel deductions or one-time immersive flags. SDL remains the owner of fullscreen visibility changes.

Insets callbacks coalesce into one posted application after layout finishes. Padding and `requestLayout` run only when the computed padding changes, avoiding requests issued inside `onLayoutChange` that Android can discard. Debug builds capture parent padding, actual child position/size/layout parameters, and SurfaceHolder buffer bounds together on the following pre-draw; identical observations are deduplicated. This trace is disabled in non-debug builds and does not alter game rules or input sessions.

`verification/verify_apk.py` checks every packaged native ELF load segment and ZIP offset for 16 KB alignment, verifies the packaged ABI set, and lists APK contents. Also use SDK `apksigner verify --verbose --print-certs` and `zipalign -c -P 16 -v 4`. Installing, updating, playing, touching, returning from home/lock, and running in a 16 KB environment belong to the coordinator's shared device session.

Name-entry keyboard visibility belongs to the shared ImGui/SDL platform callback. The Activity explicitly requests `adjustResize`; on API 30+, IME insets join system-bar/cutout/gesture safe edges. The existing safe-area conversion subtracts fitting already performed by Android, so a framework-resized content view is not shrunk twice. API 26–29 retains the legacy system-window inset path. Geometry tests are synthetic; actual keyboard show/type/hide and Surface/native bounds are coordinator-owned phone checks.

For a bounded local audio diagnostic debug APK, pass `-PpinballAudioDiagnostics=true`. This forwards the CMake option ON and defines `PINBALL_AUDIO_DIAGNOSTICS=1` only for the shared `main` library and its `pinball_core` OBJECT target. The default is false/OFF, with no definition; omit the property for the final ordinary APK. SDL and SDL_mixer targets receive no diagnostic definition. Shared `Sound.cpp` and `winmain.cpp` compile in `pinball_core`, so the wrapper gives that OBJECT target the same private definition; a main-only definition would reach JNI but miss game audio diagnostics. No new signing key or permissions are involved.

Android 13+ uses the platform default-priority Back callback with the Activity manifest opt-in; API 26–32 and delivered legacy Back keys use an Activity dispatch interception because the SDL Surface consumes these keys. Visible IME Back follows SDL keyboard hide/stop-text-input first; game Back opens the existing pause/resume dialog. Mouse Back remains SDL-owned. Callback API types are isolated in a guarded helper and unregistered at Activity destruction. Compilation and package checks do not replace actual-device Back/IME validation.
